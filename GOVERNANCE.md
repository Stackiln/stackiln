# Governance

Stackiln currently uses a maintainer-led model.

Christian Relf is the founding maintainer and release steward. Maintainers review contributions, set release scope, moderate community spaces, and protect the project's architecture, security baseline, and compatibility promises.

Decisions should be made in the open through issues, discussions, pull requests, and architecture decision records. Maintainers seek consensus and explain material trade-offs. When consensus cannot be reached, the release steward makes the final decision and records it where it affects future contributors.

Consistent contributors may be invited to become maintainers based on sustained technical judgement, constructive review, reliable participation, and adherence to the Code of Conduct. A maintainer may step down at any time or be removed for inactivity, a serious Code of Conduct breach, or actions that put users or the project at risk.

Changes to this governance model require a public pull request and approval from the release steward. If ownership changes, repository administration, release credentials, security reporting, and this document must be updated together.
